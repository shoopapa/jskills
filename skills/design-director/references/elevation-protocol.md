# Functional to finished

Run substantive refinement passes in order. Each pass should fix an observable weakness. For a small artifact, passes can be brief; for a public or high-stakes deliverable, render between them.

## 1. Establish a truthful baseline
Build the requested content, calculations, navigation, forms, and exports. Use real data where available; clearly label illustrative content. Check the primary user task. Record a baseline screenshot/render when it will help comparison.

## 2. Choose an art direction
Write a brief internal direction: audience, main action, visual character, existing constraints, and focal technique. Example: 'A practical production-office worksheet: compact labels, strong alignment, a real printable poster beside the setup form, one blue action accent.' Avoid vague instructions like 'make it premium'.

## 3. Recompose
Fix reading order, proportions, grouping, and hierarchy before touching decorative details. Give primary content enough space; remove repeated containers and redundant copy. Check the first viewport or first page answers the reader's basic questions.

## 4. Tune the system
Set a restrained type scale, color roles, spacing rhythm, border behavior, and action hierarchy. Use the technique catalog selectively. Keep interactions predictable. Repair ambiguous units, inaccessible contrast, dense wrapping, and inconsistent alignment.

## 5. Refine the edges
Inspect real empty, filled, error, loading where applicable, success, and exported states. Check long titles, small screens, keyboard focus, page breaks, printable output, and data edge cases. Confirm cosmetic edits did not break behavior. Edit microcopy for directness and specificity.

## 6. Render and challenge
Use the interrogation checklist against the actual artifact. Compare with the baseline: did the change clarify the task, reduce effort, improve reading, or give the output an appropriate character? If it only added visual novelty, reconsider it. Fix the most consequential remaining issue and render again.

## Completion condition
Deliver when the core task works, content is accurate, the hierarchy is obvious, required layouts/exports have been inspected, and no concrete design defect remains. Do not iterate indefinitely to chase personal taste. If a requested check cannot run, state the limitation and deliver what can be verified.
